# Throughput and Concurrency

판정 기준 하나: **이 코드가 프로젝트의 계약 물량(현재 유입량이 아니라)과 다중 인스턴스
배포에서 그대로 도는가.** 아니면 핫패스에 넣지 말 것.

핫패스 = 요청 1건이 지나는 경로, 큐·배치 소비 루프, 콜백 1건 처리.
핫패스 밖(기동 1회, 일 배치, 관리 화면)은 이 문서의 금지 대상이 아님.

아래 사례 열은 원 프로젝트 사례를 일반화한 것이므로, 이식한 프로젝트에서는 자기 코드의
실제 사례로 갈아끼울 것.

## 지켜야 할 규칙

- 다건 저장은 `batchInsert(List)`. 단건 insert 메서드를 인터페이스에 두지 않음
- 목록 조회·삭제에 항상 상한. 조회 `LIMIT`, 삭제는 chunk 루프, 설정값은 `Math.max` 로 하한 강제
- 메모리 축적처에 상한 또는 만료. 없으면 무한 성장
- 워커 스레드는 이름·개수·종료 시간을 설정으로 명시하고 `SmartLifecycle` phase 로 우아하게 종료
- 공유 자료구조는 스레드 소유권을 javadoc 으로 선언("push 멀티스레드 / pop 단일 스레드")
- 대용량 바이트는 스트리밍. `byte[]` 전량 적재 금지
- 외부 HTTP 호출은 connect/read/write 타임아웃 전부 명시
- 큐·맵 크기는 Micrometer gauge 로 노출

## 금지

| 금지 | 사례 |
|---|---|
| **핫패스 건당 DB 왕복.** 루프 안의 INSERT/SELECT 는 루프 밖 batch 로 | 수신자 루프 안 INSERT 가 건마다 1회 -> 뒤따르는 batchInsert 이득 상쇄 |
| **핫패스 건당 행 잠금.** `SELECT ... FOR UPDATE` 를 건마다 잡으면 같은 키의 요청이 전면 직렬화됨 | 수신자마다 `FOR UPDATE` -> 같은 클라이언트의 동시성이 1로 수렴 |
| **잠금 안의 I/O.** `synchronized`/`lock` 안에서 파일·DB·네트워크 금지. 잠금은 메모리 갱신만 감쌀 것 | 동기화 블록 안 파일 read+write -> 디스크 지연이 전 요청 대기로 전이 |
| **건당 파일 I/O.** 시퀀스·카운터는 메모리에서 발급하고 파일은 블록 예약 또는 기동 1회만 | 시퀀스 발급기가 요청마다 exists+read+write 3회 -> 메모리 발급으로 교체 |
| **상한 없는 메모리 누적.** 파일·DB 전량을 `List` 에 모은 뒤 처리 금지. 배치 단위로 읽어 그 자리에서 소비 | 복구 코드가 보존분 전 줄을 List 에 적재 -> 힙 초과 |
| **스레드 간 공유 필드에 `volatile`/`final`/`Atomic*` 없음.** 감시 스레드가 쓰고 요청 스레드가 읽는 값은 가시성 보장 필수 | 설정 감시 스레드가 쓰는 플래그를 일반 필드로 읽음 -> 설정 변경 미반영 |
| **비-final `static` 을 인스턴스 생성자에서 대입.** 불안전 발행 + 테스트 격리 붕괴 | 매핑 팩토리의 static Map 을 생성자에서 채움 -> 테스트 간 상태 공유 |
| **`ThreadLocal.set` 후 `remove` 없음.** 풀 스레드에 객체가 잔류함 | 응답 홀더 ThreadLocal 에 set 만 있고 remove 없음 -> 풀 스레드에 잔류 |
| **호출마다 무거운 객체 생성.** `ObjectMapper`, `SimpleDateFormat`, `DateTimeFormatter`, 스레드 풀은 필드·빈으로 | 서비스 메서드 안 `new ObjectMapper()`, 리포지토리 안 `new SimpleDateFormat` -> 호출마다 생성 비용 |
| **매 호출 달라지는 SQL 문자열.** 타임스탬프·값을 SQL 에 `String.format` 으로 넣으면 statement 캐시가 매번 미스 | 로그용 시각을 SQL 주석으로 삽입 -> statement 캐시 매번 미스 |
| **종료 조건 없는 루프.** chunk 루프에는 최대 반복 횟수 또는 시간 상한 | `do-while (deleted >= batchSize)` -> 유입이 삭제보다 빠르면 끝나지 않음 |
| **읽는 코드 없는 상한 설정.** yml 에 상한처럼 보이는 값을 두고 코드가 안 읽으면 착각만 남김 | yml 상한 값을 읽는 코드 없음 -> 착각만 남김 |

## 필수

- 동시성 코드는 "어떤 스레드가 어떤 상태를 소유하는가"를 클래스 javadoc 한 줄로 선언할 것.
  잠금이 있으면 무엇을 지키는지, 없으면 왜 없어도 되는지(바이트 영역 분리, 단일 writer) 명시.
- 배치 크기·윈도우·큐 상한은 상수 또는 `@ConfigurationProperties` 로 드러낼 것. 리스트 크기를
  그대로 배치 크기로 쓰지 말 것.
- 성능 주장은 숫자로. "빠르다/느리다" 금지. 잠금·직렬화 비용은 측정해 태스크 파일 구현 지침에 그 결정의 이유로 기록할 것.
